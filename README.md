# pelican-bench

**把「AI 画的这张图到底行不行」从感觉变成数。** 用「鹈鹕骑自行车」基准出题，用 `svgcheck.py` 把产出的 SVG 量成一张可对比的体检单。

> ### 起因
>
> 一份 AI 一次性生成的「鹈鹕骑车」SVG，**零件一个不缺**：24 根真辐条（每轮 12）、双三角车架、曲柄 + 两只踏板、车把带立管、前叉、**下垂的大喉囊**、白颈、深棕身、翅/颈/喙三处羽毛笔画、瞳孔带高光、2 个渐变、2 个动画关键帧（而且**曲柄和轮子同周期转动**）。
>
> 可它有 3 处硬伤，全在"关系"上：
>
> | 现象 | 实测 |
> |---|---|
> | **鹈鹕背对骑行方向** | 喙尖 x=420 ← 喙根 555 ← 眼在 **607**（眼在喙根右侧 ⇒ 头朝**左**）；而车朝**右**（前叉 `(575,350)→(710,515)` 接的是右边那只轮） |
> | **路面线横穿两只轮子** | 轮心 y=515 r=92 ⇒ 触地 y=**607**；路面 stroke 在 y=**520**，差 **87px**（轮圈是 `fill:none`，线会从轮子里透出来） |
> | **座垫画在了车把上** | 座垫 `(555,345)-(595,345)` 中点 x=**575** = 车把根部 `(575,350)` 正上方；它该在座管顶端 `(500,410)` |
>
> ⇒ **"零件齐全"是最容易骗过眼睛的合格证。** 真正会坏的是部件之间的**关系**：朝向一致、是否真的接触（轮↔地、脚↔踏板）、挂点是否在它该在的骨架上。
>
> 这个仓库就是给这件事配一把尺子。

## 这个基准是什么

「鹈鹕骑自行车」（*pelican riding a bicycle*）是 [Simon Willison](https://simonwillison.net/) 从 2024 年 10 月起对几乎每个新模型都跑一遍的非正式基准。题面只有一句：

```
Generate an SVG of a pelican riding a bicycle.
```

**为什么这么管用**：SVG 逼模型直接吐出坐标、路径、viewBox —— 把「空间与几何推理」变成 token；一渲染就是图，跨模型比对一眼见高下。而这些失败**在 MMLU / LMArena 这类常规榜单上根本不体现**（它们是"比例歪了、部件放错位置"级别的坏，不是"答错题"级别的坏）。

本仓库**不做排名、不判"是哪个模型"**，只做一件事：**让两份产出的差别变成可以逐项对照的数**。

## 快速开始

```bash
python svgcheck.py fixtures/sample-pelican.html                      # 单份体检
python svgcheck.py fixtures/sample-pelican.html fixtures/bad-minimal.svg   # A/B 对照
python svgcheck.py --check                                           # 尺子自己的自检（9 条）
```

零依赖，Python 3.8+。

## 它量什么 / 不量什么

### 量（客观可算，出数）

| 项 | 判据 |
|---|---|
| 轮子触地 | 轮底 y vs 最低那条水平线 → **贴地 / 悬空 / 沉入**（容差 ±6px） |
| 地面线穿轮 | 水平线 y 是否落在轮子内部 |
| 两轮分离 | 中心距 vs 半径和（相交基本就废了） |
| 部件齐备 | 辐条数、曲柄、腿、羽毛笔画、**渐变数、关键帧数** |
| 画布余量 | 轮底到 viewBox 底的距离 |

### 不量（列成人工核对清单打印出来）

① 鸟的朝向 ② 脚在不在踏板上 ③ 有没有喉囊 ④ 喙够不够长 ⑤ 有没有坐在座垫上 ⑥ 有没有眼睛

**为什么不硬判**：这类语义关系用正则猜不可靠，**猜错了就是诬告**。脚本宁可少说一句。

同一把尺子，量两份产出（下面是 `python svgcheck.py fixtures/sample-pelican.html fixtures/bad-minimal.svg` 的真实输出，末尾两份相同的「人工核对清单」已略）：

```
■ sample-pelican.html   6169 bytes
  画布 viewBox = [0.0, 0.0, 1100.0, 620.0]
  元素：path 19 · line 25 · circle 13 · ellipse 2 · rect 2
  渐变 2 个 · @keyframes 2 个 ['spin', 'bob'] · animation 声明 3 处

  [几何一致性 —— 客观可算]
  轮子最低点 y=607，画布底 y=620，留白 13px
  水平线 y=520（path-H）  ← 落在轮子内部：轮底 y=607，线比轮底高 87px
  水平线 y=560（path-H）  ← 落在轮子内部：轮底 y=607，线比轮底高 47px

  ⚠️  轮子**沉入线下**：轮底 y=607，最低水平线 y=560，低了 47px

  羽毛笔画：4 处  ✅
  腿：1 处  ✅
  翅：未检测到（可能是命名习惯不同，**不能当作没有**，需人工看图）
  渐变着色：2 个  ✅
  动画：有 2 个关键帧 / 3 处声明  ✅

  画布 viewBox = [0.0, 0.0, 100.0, 100.0]

  [几何一致性 —— 客观可算]
  轮子最低点 y=80，画布底 y=100，留白 20px
  水平线 y=90（rect(扁长)）
  ✅ 没有水平线穿过轮子
  ⚠️  轮子**悬空**：轮底 y=80，最低水平线 y=90，高出 10px
```

**尺子能分辨**：辐条 **24 vs 0** · 渐变 **2 vs 0** · 关键帧 **2 vs 0** —— 不是一把永远说"好"的尺子。

顺带一个**真实收获**：上面 `sample-pelican.html` 那两行 `喉囊/翅 未检测到` 是**假阴性** —— 它明明画了很大一个下垂的喉囊和一只翅膀，只是没写 `class`。这正好演示了第 2 条工程笔记：**"我没搜到" ≠ "它没有"**。

## 工程笔记：几处容易被忽略的取舍

**1. 首先得有一把能说"不好"的尺子。**
`--check` 里放了 9 条断言，并专门造了 `fixtures/bad-minimal.svg` 当对照 —— 因为**一把永远说"好"的尺子等于没有**。开发中它一度对着"圈都不全"的输入也照样打 ✅。

**2. "检测不到" ≠ "没有"。**
搜不到 `class="wing"` 只说明**命名习惯不同**，不代表作者没画翅膀。脚本一律输出「未检测到，**不能当作没有**」。这条来自一次真实的假阴性：第一版报告"喉囊未检测到"，可那份产出明明画了很大一个下垂的喉囊，只是没写 class。

**3. 解析器自己踩的两个坑（都已修，留作记录）**
- 只解析 `<svg>` 块 ⇒ **丢掉了写在 `<head><style>` 里的 `@keyframes`**，把"有动画"报成"无动画"（关键帧在 SVG 块之外！）
- 地面只认 `<line>` 和 `path…H` ⇒ **漏掉用扁长 `<rect>` 画的地面**（那也是常见画法）

⇒ 启示：写解析器时，**"我没搜到"和"它没有"之间隔着一条河**。

**4. "验不了 ≠ 通过"。**
找不到地面线时输出 `⏭ 跳过`，**不记作 ✅**。同理，一档都量不到就不该给结论。

**5. 只量关系，不量"好不好看"。**
审美没有判据，关系有。所以脚本对"这张图美不美"一个字节都不说。

## 已知边界

- **正则解析坐标**：对机器生成的 SVG（大量绝对坐标 `M/L/Q`）够用；遇到大量 `transform` 或相对坐标（小写 `m l q`）会偏 ⇒ 那就回落到人眼看。
- **"推定车轮"取半径最大的两个圆**：画风特殊的产出可能认错。
- **只读**：不修改任何被检查的文件。
- **不判断"这是哪个模型画的"**：模型自报身份是客户端人设，不是后端证据；这个仓库只谈产出、不谈归属。

## 题面与读图须知

见 [`prompts/pelican-prompt.md`](prompts/pelican-prompt.md)：包含 v1 原版、v2 升级版（要求逐条可核），以及**读图时该看什么**。

⚠️ **两条重要提醒**（免得把它当铁证）：
1. **连真旗舰都画得歪。** 所以"画得差"本身不算证据，**"差得多"**（同题对照）才是信号。
2. **必须控制变量**：同题面、同客户端、**thinking / reasoning 开着**。否则你测的是 harness，不是模型。
